# 质量漂移监测设计

## 1. 要解决的问题

固定阈值警报把所有超阈值的组一视同仁地推送，旺季切换产地后存在两类失效：

1. **结构变化被当成异常**：产地、等级、班次构成每天在变，新产地本就与老产地不在同一水平，却被拿来比较，警报刷屏。
2. **真实漂移被淹没**：某条产线持续偏移时，警报和一次性噪声混在一起，复核人员无法区分，也看不到比较依据。

本设计新增分层漂移监测层（`monitoring.py` + `events.py`），不替换原有固定阈值警报（安全红线仍保留），而是输出一套样本量自适应、可解释、事件化、带学习护栏的监测结果。

## 2. 分层与可比性：只与可比对象比较

**层（stratum）= 产线 × 产地 × 等级 × 班次**（`monitoring.stratum_key`）。

- 参照只取**同层**的历史窗口（`eligible_reference`），从不跨产地、跨等级、跨班次比较。
- 新产地首次出现时同层没有历史，输出 `no_comparable_baseline` 并说明原因，而不是借一个老产地充当参照。
- 参照必须达到资格门控（`min_reference_days` / `min_reference_kg` / `min_reference_diameter`），门控不过同样输出不可比，不硬算。
- 样本可带 `shift` 字段区分班次；缺省回落 `default`，与旧数据兼容。

“构成变化”因此天然被吸收：今天 east 抽得多、west 抽得少，只改变各层样本量，不改变层内比较对象。

## 3. 样本量自适应：抽得多不更容易报警，抽得少不冒充正常

每个指标的信号必须**同时**通过两道门（`evaluate_window`）：

1. **统计门**：检验统计量通过 FDR 控制（见第 5 节）。
2. **效应门**：估计效应量不低于最小实际偏移（`min_damage_effect` / `min_diameter_effect_mm`）。

两者缺一不可，因此：

- 大样本下极小的、无业务意义的波动即使统计显著，也会被效应门拦下，理由中显式给出实际效应与门槛。
- 小样本下噪声被 **Beta-二项收缩**（`_shrink_damage`）拉回同层基线，先验强度取参照期累计抽检重量；当前窗口重量越小，收缩越强。
- 当前窗口抽检重量低于 `min_window_kg` 时输出 `evidence_insufficient`。**证据不足与确认正常是两个不同状态**：前者不进入 FDR 检验族，也不会被当作“无异常”。

指标定义：

| 指标 | 检验 | 方向 |
| --- | --- | --- |
| 破损率 | Beta 收缩后均值对基线率的单侧上尾 z 检验 | 仅关注升高 |
| 规格偏差（直径均值） | 对基线均值/标准差的双侧 z 检验 | 双向 |

参照期直径恒定（标准差为 0）而当前取值改变时，无法估计离散度，显式输出 `structural_change`，不进入检验族，交人工判断——这正是“正常换批”最常见的形态，系统不假装能对它算 p 值。

## 4. 可解释性：每个判定都带依据和比较对象

每条 finding / 事件证据携带：

- `stratum`、`window`、状态与具体 `reasons`；
- 参照基线：覆盖的窗口日 `window_days`、样本标识 `sample_ids`、参照指纹 `reference_fingerprint`；
- 当前估计、基线估计、效应量、z 值、p 值、收缩先验参数；
- 证据样本指纹 `evidence_fingerprint`，用于测量更正后的溯源。

复核人员看到的是“这条线、这个产地、这个等级、这个班次，与哪几天的哪些样本比，差了多少，统计把握度如何”，而不是一个裸阈值结果。

## 5. 误报控制范围（FDR 检验族）

- 检验族 = **一个评估日内，所有通过资格门控的层 × 可计算指标**，族大小由 `test_family_size` 显式输出。
- 族内采用 Benjamini-Hochberg 过程（`_bh_adjust`），控制错误发现率不超过 `fdr_q`（默认 0.05）。
- `no_comparable_baseline`、`evidence_insufficient`、`structural_change` 不进入检验族：它们不是统计判定，不占用也不稀释 FDR 预算。
- FDR 只控制“统计信号”这一层的误报；事件确认、固定阈值红线是独立机制，各自语义在输出中分开标注。

## 6. 事件化：连续窗口与相关指标汇聚成一个可跟进对象

`events.project_events` 把信号投影到**只追加**的事件台账 `data["events"]`：

- 一个事件对应一个层上的一次漂移过程；同层多指标、连续窗口的信号追加为证据条目，而不是每窗一单。
- 确认规则（`_is_confirmed`）：连续 `persistence_windows` 个有数据窗口出现信号，或同一窗口有 ≥2 个指标同时信号，状态从 `watching` 升级为 `confirmed`。
- 信号连续 `AUTO_CLOSE_GAP` 个窗口消失则 `auto_closed`，理由中明确：**自动关闭不等于确认正常，证据继续隔离**。
- 事件 ID 由层与序号指纹确定，对同一数据重放结果稳定、幂等。

### 为什么需要按日重放（replay_projection）

漂移隔离有因果顺序：第 N 日评估时，第 N−1 日的信号必须已经形成事件并隔离，才不会污染第 N 日参照。一次性对末日投影表达不了这个顺序，因此 `replay_projection` 按有数据的窗口日逐步“先算信号、再投影事件”，等价于真实日批处理。只读入口 `app.inspect` 在数据副本上重放，不修改输入。

## 7. 复核反馈如何影响参照：学习护栏

复核结论（`review_event`）只追加、不覆盖，并按结论精确控制参照资格：

| 复核结论 | 对参照学习的影响 |
| --- | --- |
| `normal_batch`（正常换批） | 仅放行**该结论作出时已存在**的证据窗口（`evidence_windows`），这些窗口随后可进入同层参照；之后出现的新窗口不在放行范围，仍隔离 |
| `true_anomaly`（真实异常） | 窗口保持隔离，不进入正常参照 |
| `instrument`（仪器问题） | 窗口保持隔离（数据不可信），等待更正测量 |

护栏规则：

- **尚未确认的异常绝不会被自动学成正常**：没有任何复核的事件证据一律隔离，`explain_quarantine` 可列出全部被排除窗口及原因。
- 放行粒度是“复核时的窗口集合”，一次 `normal_batch` 不会给同层未来的新信号背书。
- 复核后若统计与人工结论不一致（例如人工判正常但后续出现更强的新漂移），系统只写 `statistical_conflict` 并要求重新复核，**不修改、不删除人工结论**。
- 人工关闭后同层再次出现信号，同一事件重开（保留全部复核历史），而不是静默新建。

## 8. 测量更正与证据溯源

- 测量修订沿用既有 `recorded_at` / `revision` / `withdrawn` 机制（`records.latest`）。
- 每个事件证据保存 `evidence_fingerprint`；投影时重算指纹，发现更正或撤回即追加 `revisions` 条目（旧指纹、新指纹、受影响样本），事件状态置为 `evidence_revised`。
- 撤回记录已被 `latest` 过滤，指纹计算直接读取原始行，确保“撤回”这个动作本身可被追踪。
- 被撤证据若曾支撑事件，事件保留并标记修订，可一路追到被撤掉或改变的证据；更正后该窗口可能不再产生信号，但事件不会被悄悄关闭。
- 复核时同时留存当时的证据指纹列表，事后可核对人工结论基于的是哪一版证据。

## 9. 状态语义汇总

| 状态 | 含义 | 是否进入参照 |
| --- | --- | --- |
| `normal` | 通过门控且未达信号标准 | 窗口本身可作未来参照（无事件隔离时） |
| `signal` | 通过 FDR + 效应门的统计信号 | 进入事件并隔离，待复核 |
| `evidence_insufficient` | 样本量不足，无法判定 | 不判定、不报警、不冒充正常 |
| `no_comparable_baseline` | 无同层可比参照（如全新产地） | 不比较、不报警 |
| `structural_change` | 零方差下的取值改变，疑似换批 | 不做统计检验，转人工 |
| 事件 `watching/confirmed` | 漂移跟踪中 | 证据隔离 |
| 事件 `auto_closed` | 信号消失自动关闭 | **仍隔离**，非确认正常 |
| 事件 `evidence_revised` | 支撑证据被更正/撤回 | 隔离，等待重新评估 |
| 事件 `closed` | 人工复核终结 | 仅 `normal_batch` 放行的窗口解除隔离 |

## 10. 配置项

见 `monitoring.DEFAULT_CONFIG`，可通过 `configure(overrides)` 覆盖，未知键直接报错。所有门控参数集中一处，便于评审调参，不允许散落在判定逻辑里。
